### 1. Описание функциональности монолитного приложения

**Управление отоплением:**

- Пользователи могут:
	- Получить текущие параметры абсолютно всех сенсоров
	- Получить текущие параметры сенсора по ID
	- Создать новый сенсор
	- Изменить параметры существующего сенсора
	- Удалить сенсор
	- Обновить значение, статус, время сенсора
- Система поддерживает:
	- Хранение информации о сенсорах (в таблице sensors в БД smarthome)
	- REST API для выполнения CRUD операций с сенсором (handlers/sensors.go)

**Мониторинг температуры:**

- Пользователи могут:
	- Получить текущие параметры абсолютно всех сенсоров из БД и их значения из внешнего API (по ID)
 	- Получить значение сенсора из внешнего API по location
- Система поддерживает:
	- Единственный тип сенсора "temperature"
	- Интеграцию с внешним API для получения значения сенсора (services/temperature_service.go).

### 2. Анализ архитектуры монолитного приложения

- Язык программирования: Go
- База данных: PostgreSQL
- Архитектура: Монолитная, все компоненты системы (обработка запросов, бизнес-логика, работа с данными) находятся в рамках одного сервиса app.
- Взаимодействие внутреннее:
	- Синхронное, запросы обрабатываются последовательно.
	- Приложение управления, база данных, приложение температуры запускаются в трех отдельных Docker-контейнерах.
	- Создается кастомная сеть smarthome-network.
- Взаимодействие внешнее:
	- осуществляется через REST API.
- Масштабируемость: Ограничена, так как монолит сложно масштабировать по частям. Плюс нужно добавить балансировщик нагрузки.
- Развертывание: Требует остановки всего приложения.

### 3. Определение доменов и границы контекстов

Домен: управление сенсорами
	поддомен управления сенсорами
		контекст: управление сенсорами
			сущности: сенсор;
			объекты-значения: поля сенсора;
			агрегаты: сенсоры;
			репозитории: репозиторий сенсоров;
			сервисы: сервис управления сенсорами.
Домен: мониторинг значений сенсоров
	поддомен получения значений температуры
		контекст: получение значений
			сущности: ответ API;
			объекты-значения: id, локация, температура;
			агрегаты: ответ API;
			репозитории: нет;
			сервисы: сервис получения значений температуры.

# Задание 5. Работа с docker и docker-compose

Перейдите в apps.

Там находится приложение-монолит для работы с датчиками температуры. В README.md описано как запустить решение.

Вам нужно:

1) сделать простое приложение temperature-api на любом удобном для вас языке программирования, которое при запросе /temperature?location= будет отдавать рандомное значение температуры.

Locations - название комнаты, sensorId - идентификатор названия комнаты

```
	// If no location is provided, use a default based on sensor ID
	if location == "" {
		switch sensorID {
		case "1":
			location = "Living Room"
		case "2":
			location = "Bedroom"
		case "3":
			location = "Kitchen"
		default:
			location = "Unknown"
		}
	}

	// If no sensor ID is provided, generate one based on location
	if sensorID == "" {
		switch location {
		case "Living Room":
			sensorID = "1"
		case "Bedroom":
			sensorID = "2"
		case "Kitchen":
			sensorID = "3"
		default:
			sensorID = "0"
		}
	}
```

2) Приложение следует упаковать в Docker и добавить в docker-compose. Порт по умолчанию должен быть 8081

3) Кроме того для smart_home приложения требуется база данных - добавьте в docker-compose файл настройки для запуска postgres с указанием скрипта инициализации ./smart_home/init.sql

Для проверки можно использовать Postman коллекцию smarthome-api.postman_collection.json и вызвать:

- Create Sensor
- Get All Sensors

Должно при каждом вызове отображаться разное значение температуры
